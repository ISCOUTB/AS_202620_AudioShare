# Introducción y objetivos

## Resumen de requisitos

AudioShare busca permitir que un dispositivo emisor comparta audio en
tiempo real con múltiples dispositivos receptores conectados a la misma
red Wi-Fi.

El sistema contará con una aplicación móvil desarrollada con Flutter
como cliente y un backend responsable de gestionar las sesiones, el
audio y la sincronización de la reproducción.

Los requisitos funcionales son poder: 

- Crear una sala de audio.
- Hacer que varios usuarios se unan con un código.
- Transmitir el audio desde un dispositivo emisor hacia otros receptores.
- Controlar individualmente el volumen de los receptores
- Hacer que el moderador administre los participantes.

El primer prototipo funcionará y estará enfocada sobre dispositivos en una red de wifi local.
  
# Objetivos de calidad

Buscaremos principalmente los siguientes aspectos: 

- Rendimiento: Tratar de mantener una baja latencia durante la transmisión para que no haya mucho retraso al escuchar el audio. Este objetivo es importante para los usuarios receptores y el usuario emisor, ya que se necesita que el audio se reproduzca de manera sincronizada.

- Disponibilidad: Tratar de mantener activa y funcional la transmisión el mayor tiempo posible siempre que exista una conexión estable entre los dispositivos. Es importante para los usuarios receptores, el usuario emisor y el moderador, ya que todos dependen de que la sala permanezca disponible durante la reproducción.

- Tolerancia a fallos: Buscar que en caso de una interrupción en la conexión, se pueda poder reconectar. Es importante para los usuarios receptores y el usuario emisor, ya que una interrupción de la conexión no debería obligarlos a abandonar la sala y comenzar nuevamente el proceso de conexión.

- Escalabilidad: Permitir que una sala pueda tener y manejar a varios dispositivos receptores. Es importante para el usuario emisor y el moderador, ya que son quienes necesitan gestionar una sala con múltiples participantes y dispositivos.
