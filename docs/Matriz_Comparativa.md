# Matriz Comparativa de Arquitectura contra el Árbol de Utilidad

La siguiente matriz compara las alternativas de arquitectura considerando directamente los escenarios de calidad definidos para AudioShare. En cada escenario se identifica qué aspectos mejoran y cuáles empeoran con cada estilo, tomando como referencia los atributos priorizados en el árbol de utilidad: **rendimiento**, **disponibilidad y confiabilidad** y **usabilidad**.

| Escenario                                   | Atributo del árbol de utilidad                                     | Arquitectura por Capas                                                                                                                                                                                                                                           | Arquitectura Hexagonal                                                                                                                                                                                                                                                       | Monolito Modular                                                                                                                                                                                                                                                                                                           |
| ------------------------------------------- | ------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **EC-01 — Sincronización inicial**          | Rendimiento — Alta prioridad                                       | **Mejora:** estructura sencilla y flujo predecible para iniciar la reproducción. **Empeora:** el paso por varias capas puede agregar latencia y acoplar la sincronización con servicios/controladores.                                                           | **Mejora:** la lógica de sincronización queda aislada y puede optimizarse independientemente de la red. **Empeora:** puertos y adaptadores agregan complejidad inicial al flujo de transmisión.                                                                              | **Mejora:** comunicación rápida entre `session`, `audio` y `sync`, reduciendo sobrecarga entre componentes. **Empeora:** al compartir proceso, una mala implementación en un módulo puede afectar el rendimiento global.                                                                                                   |
| **EC-02 — Variación moderada de latencia**  | Rendimiento + Disponibilidad y confiabilidad — Alta prioridad      | **Mejora:** separación clara de responsabilidades facilita localizar el manejo de la conexión. **Empeora:** la propagación de eventos de red a través de las capas puede dificultar una respuesta rápida ante variaciones de latencia.                           | **Mejora:** permite cambiar o adaptar el mecanismo de comunicación sin modificar la lógica central; favorece tolerancia a cambios de red. **Empeora:** requiere mayor infraestructura de abstracción y configuración para manejar los distintos adaptadores.                 | **Mejora:** los módulos pueden coordinarse rápidamente en memoria y mantener la lógica de recuperación aislada. **Empeora:** una falla grave dentro del proceso puede comprometer otros módulos del sistema.                                                                                                               |
| **EC-03 — Pausa y reanudación**             | Rendimiento — Alta prioridad                                       | **Mejora:** el flujo controlador-servicio es fácil de entender y mantener. **Empeora:** los comandos `PAUSE` y `PLAY` deben atravesar las capas, aumentando el acoplamiento y potencialmente la latencia.                                                        | **Mejora:** los comandos pueden representarse como eventos/puertos y enviarse al mecanismo de transporte sin modificar el dominio de sincronización. **Empeora:** requiere definir explícitamente interfaces para estos eventos y sus adaptadores.                           | **Mejora:** `sync` puede coordinar directamente las órdenes de reproducción con `audio`, manteniendo baja sobrecarga. **Empeora:** los límites entre módulos deben mantenerse estrictamente para evitar dependencias internas.                                                                                             |
| **EC-04 — Incorporación de nuevo receptor** | Usabilidad + Disponibilidad y confiabilidad — Alta/media prioridad | **Mejora:** el flujo de incorporación puede organizarse de forma sencilla entre controlador, servicio y datos. **Empeora:** agregar lógica de sincronización durante la incorporación puede distribuirse entre varias capas y aumentar la complejidad del flujo. | **Mejora:** la incorporación puede desacoplarse de la infraestructura concreta de comunicación, facilitando diferentes mecanismos de conexión. **Empeora:** la cantidad de puertos y adaptadores puede hacer más complejo un flujo que debería ser sencillo para el usuario. | **Mejora:** `session` puede gestionar la incorporación mientras `sync` coordina la sincronización, manteniendo el proceso dentro del mismo servicio y facilitando una respuesta rápida. **Empeora:** el crecimiento del número de módulos puede exigir mayor disciplina para conservar los límites y evitar acoplamientos. |

## Relación con la decisión arquitectónica

La comparación muestra que las tres alternativas pueden satisfacer los escenarios, pero presentan diferentes compromisos frente al árbol de utilidad.

* **Arquitectura por Capas:** presenta la menor complejidad inicial, pero ofrece menor aislamiento para la lógica de sincronización y puede introducir mayor acoplamiento entre la lógica de negocio y la infraestructura.
* **Arquitectura Hexagonal:** ofrece el mayor aislamiento de la lógica central y facilita la sustitución de mecanismos de comunicación, pero introduce mayor complejidad inicial mediante puertos y adaptadores.
* **Monolito Modular:** ofrece un equilibrio entre rendimiento, aislamiento y complejidad. Permite separar `session`, `audio` y `sync` dentro del mismo proceso, manteniendo una comunicación interna rápida y evitando la complejidad operacional de distribuir el sistema.

## Decisión

Se selecciona **Monolito Modular** como alternativa para AudioShare porque presenta el mejor equilibrio entre los atributos de calidad priorizados. En particular, favorece el rendimiento necesario para EC-01, EC-02 y EC-03, permite organizar el manejo de sesiones y nuevos receptores requerido por EC-04 y mantiene una complejidad de implementación razonable para el alcance del prototipo.

La decisión es coherente con la estructura actualmente implementada en el repositorio, donde los módulos `session`, `audio` y `sync` se mantienen separados y su composición se realiza desde `src/app.ts`.
